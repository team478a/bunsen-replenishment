# ブンセン補充出荷指示アプリ

ムロオ神戸・杉戸の確認済み在庫、既存の日別需要予測、補充条件から必要補充数量を計算するWindows用の独立アプリです。最新のJAN・物理PL方式は確定入庫・輸送中数量を計算対象外とします。**ブンセン側在庫の確認・照合は不要です。特定業務Excelには依存しません。** 需要予測エンジンやAI判断は追加しません。

必要補充指示は実出荷実績・供給可能在庫と別の情報です。実CSV接続・業務設定の正式値・現場受入は未確認。samples以下の数量・設定・確認済み宣言は架空例です。

## JAN・物理PL方式（現行0.7.10）

「JAN・倉庫別PLマスタ」で13桁JAN、品名、概算期限、神戸/杉戸それぞれの物理1PLのP数を確認登録できます。requirements.csvを含む一式を取り込むと、必要Pと物理PL切上げ後Pを分けて計算し、修正も整数PLに限定します。確定入庫・輸送中・製造・ブンセン在庫は使いません。入庫が確認済み0件という意味ではありません。

確認済み様式のムロオ「在庫一覧受払」PDFを自動読取し、13桁JAN・現在庫の商品合計・C入を取得します。日常画面の「在庫PDFを読み取る」から原本を表示し、数量を確認・修正して保存できます。ZIPは対象日のPDFを1件ずつ選択します。空欄は初期状態で未確認とし、原本・ハッシュ・確認者・基準日時・空欄ルール・修正根拠を保存します。[操作と対応範囲](docs/pdf-inventory-reader.md)。

[CSV契約・操作・架空試用手順](docs/jan-pl-contract.md)。旧replenishment.csvは従来の入庫反映/甲切上げとして保持し、新方式へ自動変換しません。実データ・外部倉庫コード・業務条件を推定登録していません。

## 14日配送計画・概算期限

「14日配送計画」タブで、取り込んだムロオデータと商品別の期限種別・期限日数から配送便を作成します。**今日製造した場合の概算期限**を計算実行日で固定し、実期限と区別します。製造日・製造数量・ロット・ブンセン在庫は不要です。

商品マスタの期限項目は管理設定から理由・担当者付きで登録できます。未登録商品は計画を停止します。最大16PL枠/便、1PL1商品（甲端数も1枠）で分便し、担当者確認後に正式配送予定を保存します。計画は実出荷指示/実績とは別で、費用や便数の最適解を保証しません。

倉庫別Excel/PDF/HTMLと計画JSONを出力し、保存履歴から再表示できます。期限内需要との比較は参考警告で、予測不足は確認不能と表示します。実在庫の期限切れ・廃棄量は算出しません。架空例はsamples/delivery-plan（固定在庫基準2026-11-09、32日分予測）です。[計算・保存・制約の詳細](docs/delivery-plan.md)。

## 起動

Windows x64試用ZIP全体を展開し、BunsenReplenishment.exeを起動します。Python・Excel本体・Docker・常時ネット接続は不要です。署名なしの試用版です。

ZIP直下のアプリフォルダーに「操作マニュアル.pdf」（12ページ）を同梱します。JANマスタCSVのひな形と一括登録手順も掲載しています。

ソース版はPython 3.12（Tcl/Tk込み）で実行します。

```powershell
python -m pip install -r requirements-runtime.txt
python -m bunsen
```

## 画面デザイン

日常画面は「補充出荷」と「履歴」に集約しました。マスタ・補充条件・14日配送計画・診断・バックアップは「管理・その他」メニューから開きます。重複する確認チェックを廃止し、保存・確定ボタン自体を担当者の確認操作とします。欠損・未確定予測・単位の検証は継続します。[操作仕様](docs/simple-ui.md)。

## 日常操作

0.7.7では「乾麺倉庫の実在庫CSV取込」と「実在庫と指示数量を照合」を追加しました。JAN・実在庫P・他出荷向け取置Pを取り込み、基準日時・確認者・原本を保存します。神戸・杉戸を合算して数量照合し、必要補充計算は変えません。[CSV・操作仕様](docs/dry-stock-intake.md)。

0.7.5では「全JANマスタを初期化（バックアップを保存）」と「データ保存先・空のデータで検証」を追加しました。旧版が展開先に関係なく共有DBを開いていた動作を改めています。利用者の既存データは変更せず、必要な場合だけ明示的に旧共有先を開けます。[説明と手順](docs/storage-and-reset.md)。

0.7.4ではJANの上書き編集・補充対象外（削除）・対象への復帰と、CSVによる対象一覧の置換を用意しました。PDF未掲載と数量欄の空欄を分け、明示的な対象外JANは在庫・予測の計算から除外します。[操作手順](docs/jan-scope.md)。

0.7.6では倉庫番号・倉庫名を表示し、補充条件4項目を神戸・杉戸で別々に保存します。到着までの日数も倉庫ごとに計算へ適用します。商品別設定はありません。以前の共通条件は履歴に保持し、倉庫別に再確認するまで新規画面へ自動適用しません。補充条件CSVは不要です。[入力する内容](docs/settings-guide.md)。

0.7.1ではJANマスタCSV一括登録、補充条件メニュー、PDF時刻の自動表示を追加しました。未登録JANを含む予測は警告付きで先行取込し、後からマスタ登録できます。[操作・CSVひな形・在庫日付方針](docs/master-workflow-fixes.md)。

既存予測結果は「予測CSVを取込」で準備できます。**予測出荷数量（パック）だけを採用し、大口・特売は加算しません。** 初回の倉庫コード対応は未設定です。業務確認済みの対応を指定するまで保存できません。小数Pは最後の物理PL切上げまで保持します。[取込手順・証跡・対象列](docs/forecast-csv-import.md)。

1. 出荷日を指定し、**データを開いて計算**でCSV一式のフォルダーを選びます。最初に「補充条件」で神戸・杉戸それぞれの条件を保存してください。補充条件CSVは不要です。
2. 神戸・杉戸の必要量と出荷PL、到着日を確認します。修正時だけ商品を選び、PL数・理由を入力して**修正を反映**します。
3. 担当者を入力し、**確定してExcel・PDF出力**で保存先を選びます。キャンセルした場合は確定しません。保存済みの再出力は「履歴」から行います。

計算根拠・需要予測・安全在庫・基準日時は「計算根拠・取込情報を表示」で確認できます。未確定予測や必須データ不足は正式発行できません。

管理設定は別タブです。サイクル・配送日数・安全日数・対象日数の変更根拠と担当者を保存し、変更後は全明細を再分析・再確認します。値を本番の正式値として自動採用しません。

## 架空データの試用

```powershell
python -m bunsen.tools acceptance-kit --dispatch 2026-11-14 --output C:\BunsenTrial\new-kit
python -m bunsen --trial-kit C:\BunsenTrial\new-kit
```

配布版はBunsenTools.exe acceptance-kitとBunsenReplenishment.exe --trial-kitを使用します。日付は実際の試験日へ置き換えてください。キット内samples/replenishmentを取込し、神戸120P・杉戸48Pの架空例を確認できます。samples/replenishment-provisionalは未確定予測を含みます。キットは試用DBを通常履歴から隔離し、帳票へ実出荷不可を表示します。

## 計算と単位

到着日=出荷予定日＋lead_days。対象日数=max(cycle_days,coverage_days)。各日の安全在庫は翌日からsafety_days日分の予測合計です。確認済み在庫を起点に日別需要・確定入庫を反映し、到着日以降に必要な安全在庫との差の最大値を補充必要Pとします。遅い入庫で早い不足を隠しません。

商品別の甲P=p_per_ball×balls_per_caseで切り上げ、PL＋甲へ表示します。1PL未満や1PLを超える端数を、無条件に丸ごとのPLへ切り上げません。元の必要P・換算後P・手修正P・最終確定Pを区別して保存します。

在庫basis=opening（基準日始業）/closing（基準日終業）を明示し、既に在庫へ反映された需要・入庫を重ねません。日中の途中在庫に日次予測全量を重ねる推測は行いません。実CSVとの時刻対応はデータ責任者が確認します。

## 履歴と互換性

通常履歴はアプリの展開先の`data/history.db`に保存します。画面上部に保存先を表示し、別の新規展開先は空の独立データで起動します。旧共有データは自動では開きません。[保存先・初期化](docs/storage-and-reset.md)を参照してください。旧指示・取込原本・改訂・バックアップは削除せず、旧方式の帳票として再出力できます。旧入力を新方式へ自動変換せず、新しい日常操作には使用しません。朝照合・ロット割当・供給在庫/期限/車両検証は新方式の判定対象外で、実出荷時の別業務です。

旧形式の互換性試験はLegacyApp/legacy_demo等で維持します。標準起動と固定日付デモは新方式です。

## 現場受入の準備

0.3.1-preview.1の受入キットは今日/明日補充・未確定予測・14日計画・8商品の長い品名の4シナリオを含みます。数量/16PL分便の期待結果を付けた13項目の記録と、実CSV・正式設定・実プリンター・復旧/更新の確認票を同梱します。すべて架空で、受入結果は未実施のまま生成します。

## 商品マスタの画面登録

0.4.0-preview.1では「商品マスタ」タブから、CSV未取込でも新商品の追加・既存商品の編集ができます。商品コード・商品名・1ボールのP数・1甲のボール数・1PLの甲数・出荷単位・期限種別・期限日数を確認し、担当者と理由・確認チェックを付けて保存します。1甲/1PLのP数は入力換算数から表示します。業務用の初期値は自動設定しません。

登録内容と変更前後はローカルDBへ保存され、再起動後も利用できます。日常操作で「登録商品マスタを使う」を選んで再取込すると、登録全商品を使用し、products.csvを必須にしません。未選択では従来通りCSV商品マスタを使用します。使用元と登録版を明示し、変更後は再取込・再計算・再確認が必要です。

新商品の在庫・予測・補充条件・確定入庫の網羅確認は別途整備してください。不足対象を表示して停止し、0や他商品の設定を代用しません。商品コードは編集で変更せず、別コードは新商品として追加します。削除・旧履歴の書換え・元CSV上書きは行いません。登録マスタを新規CSVへ出力することもできます。[仕様・制限](docs/product-master.md)。
