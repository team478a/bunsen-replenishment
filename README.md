# ブンセン 補充出荷指示アプリ

ムロオ神戸・杉戸の確認済み在庫と既存システムの需要予測CSVから、今日・明日の補充を検討するWindows用ローカルアプリです。需要予測エンジンは含みません。**既存CSV未確認の試作版であり、実データとの接続は未完了です。** 業務承認前は架空サンプル専用として使用してください。

## 起動・開発

Windows x64の署名なし試用ZIPをCI成果物として作成します。ZIP全体を展開して`BunsenReplenishment.exe`を起動できます。利用端末へのPython追加インストールは不要です。導入・更新・診断は[Windows試用配布](docs/windows-distribution.md)を参照してください。署名と現場受入は未完了です。

ソースから起動する場合は、Windows 10/11、Python 3.12以上（インストーラーのTcl/Tkを含む）を用意します。アプリの実行に外部Pythonパッケージ、Docker、ネット接続は不要です。

```powershell
python -m bunsen
python -m unittest discover -s tests -v
python -m bunsen.demo
```

画面で対象出荷日（サンプルは2026-11-09）とCSVフォルダーを指定します。`samples/before_morning`で取込→補充計算→仮指示、`samples/morning`を再取込して計算→不足確認・修正→正式発行を実行します。サンプルは朝在庫不足を含むため、神戸120P・杉戸120Pに修正し、両方にロット`L001`を指定すると正式発行できます。担当者名と確認チェックを入力します。数量はP入力、帳票にはPL＋甲を併記します。翌日計画は出荷日を2026-11-10にして計算しますが、将来日の正式発行は禁止します。システム日がサンプル日と異なる場合、サンプルの正式発行は固定日付で動くデモで確認してください。

帳票は倉庫別HTMLをブラウザーで開き、印刷または「Microsoft Print to PDF／PDFに保存」を選択します。PDFの自動生成は初期範囲外です。`python -m bunsen.demo`は固定日付・一時DBで全フローを再現し、`demo-output`に帳票を出力します。

通常の履歴・取込原本・計算・手修正・発行情報は`%LOCALAPPDATA%/BunsenReplenishment`に保存されます。実データはリポジトリ外で管理してください。共有DB・複数端末同時利用は対象外です。「バックアップ・復元」画面で履歴DBと帳票をまとめて保存できます。

## 方針と制約

Python標準ライブラリ＋Tkinter＋SQLiteにより、導入時の依存と更新手順を小さくします。ソースに加えて、Python・Tcl/Tk同梱の試用ZIPを提供します。署名済みexe・インストーラーは後続段階です。印刷HTMLは日本語をそのまま保持でき、ブラウザーのPDF機能を利用します。計算／検証はUIから独立しています。

必須値の欠損を0で補完しません。確認不能の対象を表示し、最小版は一件でも不備があれば正式発行全体を止めます。製造予定・未確定入庫・確定注文・代替・混載は取り込みません。需要予測と実績は混同しません。同日発行の再実行は新改訂として同日の全倉庫分を置換する扱いで、追加出荷には使用できません。旧帳票の回収・差替えは運用責任者が管理します。

詳細：[仕様](docs/specification.md)、[仮データ契約](docs/data-contract.md)、[未確定事項](docs/open-questions.md)、[実装計画](docs/implementation-plan.md)。

## 発行前検証・履歴の安全性

到着前の日別予測残高と不足リスクも表示します。後日到着する輸送中数量で前日の不足警告を隠しません。日内の入庫時刻と需要発生順は未確認として表示し、予測残高は確定在庫として扱いません。

正式発行後は再計算が必要です。別画面で同日の正式指示が発行された場合は、古い計算からの発行を停止します。履歴には「最新改訂／旧版」を表示し、再出力する旧版帳票には「出荷に使用しない」と明記します。保存済みHTML・紙・PDFは自動更新されません。改訂を確認し、旧版を回収してください。

CSV一式の専用フォルダーを用意してください。未対応CSV（注文や製造予定など）が混在すると、黙って無視せずファイル名を示して停止します。

## 複数ロットの指定

明細を選択し「複数ロットを指定」を開きます。朝在庫・賞味期限・他明細の割当を確認して、ロットとP数量を「追加・更新」します。指示総量Pは別途入力し、割当合計との一致を確認して「数量・分割を反映」を押します。数量0の割当行は削除します。単一ロットへ戻す場合も、この画面で割当を1行にしてください。

`samples/multi_lot`は架空の2ロット在庫です。神戸・杉戸とも指示総量120P、L001=72P・L002=48Pで発行できます。`python -m bunsen.demo`は単一ロットに加えて複数ロットも検証し、`demo-output/multi-lot`に帳票を出力します。

各割当は甲単位、期限と在庫はロットごと、重量は倉庫・商品ごとの総量で検証します。未割当や合計不一致は仮指示に残せますが、正式発行は止まります。分割機能は担当者による明示操作のみです。先入先出・倉庫優先配分・異なるロットを同一PLに積む条件は未承認です。

## 前日の仮指示を再開する

1. 「管理設定・履歴」で最新の仮指示を選び、「選択した最新の仮指示を再開」を押します。現在の画面内容を置き換え、日常操作へ戻ります。
2. 保存原本から数量・単一／複数ロットを復元します。担当者名と確認チェックは復元しません。再開だけで朝在庫確認が済んだことにはなりません。
3. 朝のCSV一式を「データ取込」し、「補充計算」を実行します。手修正は保持し、最新の推奨・根拠・不足と元仮指示を比較します。
4. 不足数量やロットを修正し、再確認して正式発行します。帳票と履歴には再開元番号と比較結果も残ります。

再起動後に再開できるのは、仮指示として発行・保存した内容です。未発行の画面編集は再開対象になりません。翌朝へ引き継ぐ変更は仮指示を再発行してください。再開中に仮指示を再発行すると、新しい仮改訂が再開元になります。

旧版や正式指示は再開できません。商品・倉庫の組合せが変わると自動追加・削除せず停止します。日付変更または「仮指示の再開を終了」で新規計算へ戻れます。新規計算へ戻っても保存済み履歴は削除しません。取込失敗時はデータを修正して再取込してください。

受入試験の手順と未実施項目は[受入試験](docs/acceptance-test.md)を参照してください。

## バックアップと復元

「バックアップ・復元」で、現行データフォルダー外へ新しいZIPを保存します。取込原本を含む履歴DBとreports内のファイルを保存し、ハッシュと履歴整合性を検証します。元CSVフォルダー・未発行の画面編集・別の場所のPDFは含みません。

ZIPを選択・検証し、復元先の親フォルダーを指定すると、新規フォルダーへ復元します。現行DBと帳票は上書きしません。「復元履歴を閲覧」で過去の原本・改訂・帳票を確認でき、「通常データへ戻る」で元に戻れます。切替前に必要な編集を仮指示として保存してください。

**復元履歴は閲覧専用です。新規発行はできません。** 再出力には「参考帳票・実出荷に使用しない」と表示し、view-outputへ保存します。復元した元の帳票ファイルも歴史資料であり実出荷には使用しないでください。本番復帰は、バックアップ後の出荷・改訂との照合が必要です。

GUIを起動できない場合のCLI、形式・上限・復旧上の制約は[バックアップと復元](docs/backup-restore.md)を参照してください。

## 実CSV接続前の診断・項目対応

「取込前診断・項目対応」でCSVフォルダーと対象出荷日を指定すると、商品・倉庫・日付・項目別に不備を一覧表示し、JSONと印刷用HTMLへ新規保存できます。元CSV・業務DB・現在の取込内容は変更しません。

診断対象は仮契約v0です。**診断成功は実CSV接続完了や正式発行可を意味しません。** 実ロット・数量・期限・積載は通常の正式発行フローで再検証します。実CSVの列名・単位・変換・確認者は[項目対応表](docs/csv-mapping-review.md)で未確認として整理しました。

```powershell
python -m bunsen.tools diagnose C:\input\csv --dispatch 2026-11-10 --output C:\review\diagnostic.json
python -m bunsen.tools mapping-template --output C:\review\csv-mapping-review.json
```

配布exeでは`BunsenTools.exe diagnose`と`BunsenTools.exe mapping-template`を使えます。詳細と終了コードは[取込前診断](docs/csv-diagnostics.md)を参照してください。実CSV・仕様書は引き続き未提供です。

## 現場での操作試験

試験日付の架空CSVと未実施の受入記録を新規生成し、通常履歴から分離した試用DBで操作できます。

```powershell
python -m bunsen.tools acceptance-kit --dispatch 2026-11-10 --output 'C:\BunsenTrial\受入キット'
python -m bunsen --trial-kit 'C:\BunsenTrial\受入キット'
```

配布版は`BunsenTools.exe acceptance-kit`と`BunsenReplenishment.exe --trial-kit`を使います。実際の試験日に置き換え、07時以降に試してください。検証ゲートは解除せず、帳票には実出荷不可と表示します。詳細は[受入キット](docs/acceptance-kit.md)を参照してください。実CSV接続・現場受入は未完了です。

## 4〜14日先の不足リスク参考表示

「14日参考見通し」では取込済みの倉庫在庫・輸送中と需要予測から、基準日〜14日先の補充前の参考残高を表示できます。予測欠損の影響日以降は確認不能です。仮／正式指示・手修正・乾麺在庫の割当は反映せず、出荷指示と区別します。

CLIは`python -m bunsen.tools outlook CSVフォルダー --start YYYY-MM-DD --output 新規JSON`（配布版は`BunsenTools.exe outlook`）。根拠・欠損・出力・制約は[14日参考見通し](docs/reference-outlook.md)を参照してください。未来の予測精度を保証する機能ではありません。
