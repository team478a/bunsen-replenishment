# 取込前診断と実CSV項目対応

実CSV・仕様書は未提供。診断対象は**仮データ契約v0**であり、実CSV接続完了や業務承認を示さない。実データの整備・確認責任はブンセン側にある。列名・単位・換算・文字コードを推測して変換せず、欠損を0へ補完しない。

## 画面

「取込前診断・項目対応」でフォルダーと対象出荷日を指定し、診断を実行する。入力CSVと業務DBは読み取りだけで、現在の取込データや計算内容を置き換えない。担当者の確認チェックは解除する。診断後の正式発行には、日常操作で必要なCSVを改めて取り込み、選択ロット・数量・期限・積載を再検証する。

不備は区分・ファイル・CSV行・商品・倉庫・対象日／基準日時・項目・コード・理由で表示する。横方向・縦方向にスクロールできる。JSONと印刷用HTMLを同じ名前で新規保存でき、HTMLはブラウザーから印刷・PDF保存できる。入力フォルダー内への保存、既存ファイルの上書きは拒否する。保存時に一方の出力が失敗すれば、その処理で作った出力だけを除去する。

出力には実データのコード・基準日時・不正値を含む場合がある。診断結果も実データとして扱い、リポジトリへコミットしない。元CSVの修正はデータ責任者が行い、修正後に再診断する。

## チェックの区分

| 区分 | 実施内容 | 不備・未実施の扱い |
|---|---|---|
| 入力契約 | ファイル、UTF-8、列名・列順、全必須項目、整数・日付・タイムゾーン、確認区分、重複、商品・倉庫の参照、必須組合せ | 1行の複数不備も一覧化。不備があれば取込用Datasetを生成しない |
| 計算条件 | 出荷日・到着日、必要期間の予測、予測／在庫基準日、輸送中の確認境界 | 入力契約に不備があれば未実施。連続した予測欠落は先頭日・終端日をまとめて表示 |
| 朝現物在庫 | 指定出荷日が本日か、商品別現物在庫の有無、当日朝の確認時刻・現物元・確認者 | 入力契約に不備があれば未実施。前日在庫を確認済みにしない |
| 正式出荷の最終検証 | 担当者が選択した実ロット・数量・期限・積載・倉庫横断割当 | **診断では未実施。正式発行の通常フローで必ず実施する** |

「朝現物在庫チェック実施」はチェックを行ったという意味で、条件適合済みとは限らない。不備がある場合は同じ一覧に表示する。仮契約の不備が検出されなかった場合も`formal_issue_allowed=false`を必ず出力し、実CSVとの対応・業務設定の承認はunconfirmedのままにする。

CSVの確認済み申告だけで、実際の現物確認や全ロットの網羅性は証明できない。予測に基づく到着前不足の参考警告も、欠品実績・確定在庫として扱わない。

## 読取り時点と識別

- ファイルごとの原本SHA-256は取得したバイト列（BOM・改行を含む）を識別する。
- 入力識別は観察したファイル名・有無・原本ハッシュの組合せを識別する。
- Datasetの識別は従来どおりBOM・改行を正規化した取込原文を識別する。原本SHA-256とは別物。
- CSV行番号は物理的な終端行。引用符内改行のあるレコードでは複数行にまたがる。
- ファイル一覧の行数は読取できた行数。構文エラー時に全件を読めたことは示さない。
- 複数ファイルを一括凍結する仕組みではない。書込み中ではない、確定したCSV一式を診断・取込対象として用意する。
- 第10段階から前後のCSV一覧・属性・バイト列を照合し、観測した変更・再照合不能で停止する。read_consistencyに結果を記録する。stable_observedは同一業務バッチや適合の保証ではない。[変更検査の仕様](csv-read-guard.md)を参照。
- 保存したレポートは診断時点の結果。CSVや対象日を変えたら再診断し、過去レポートを確認結果として使い回さない。

UTF-8として読めないCSVについて、CP932等への自動判定・変換は行わない。契約外CSVは列名等の観察だけを行い、データを通常取込へ渡さない。実仕様が確認できた後に明示的な対応を実装する。

## CLI

```powershell
python -m bunsen.tools diagnose C:\input\csv --dispatch 2026-11-10 --output C:\review\diagnostic.json
python -m bunsen.tools mapping-template --output C:\review\csv-mapping-review.json
```

Windows配布では`python -m bunsen.tools`を`BunsenTools.exe`に置き換える。diagnoseはJSONと同名HTMLを保存する。終了コードは0=対象範囲で不備検出なし、2=不備あり（または引数不正）、1=保存等のエラー。0でも正式発行・実CSV接続・業務承認を許可する意味ではない。

## 項目対応表

`csv-mapping-review.md`に全対象項目を列挙している。画面・CLIから、実CSVのファイル名・文字コード・基準日時・各列・単位・変換・確認者・確認日をnull／unconfirmedとしたJSONひな形も保存できる。nullは未確認であり、0や既定値ではない。

この対応表はレビュー用で、アプリの取込設定として読み込まない。ブンセン側で実仕様・確認責任者を確定してから、必要な変換・コード対応・実データ照合・現場受入を別途行う。
