# 取込中のCSV変更検出

通常取込、取込前診断、参考見通しCLI、保存原本の再読込で、共有するCSV読取処理が前後のファイルを照合します。**観測した変更を止める機能であり、原子的な一括取得や同一業務バッチの証明ではありません。**

v2では商品・ムロオ在庫・予測・確定入庫・補充条件の5ファイルを検査します。新方式で使用しない旧dry_stock/vehicles/warehouses/policiesは内容・変更検査の対象外です。

## 検査方法

1. 読取開始時のCSV一覧、ファイル識別・属性を取得する。
2. CSVのバイト列を読み取り、従来どおり列・型・確認済み宣言・参照コード等を検証する。
3. 読取後の一覧・属性を開始時と比較し、初回のバイト列と再読したバイト列を比較する。
4. 再照合中に先に検査したファイルが変わる場合も検出するため、最後にもう一度一覧・属性を比較する。

属性はOSから取得できるデバイス/ファイル識別、種類・モード、サイズ、更新日時、ctimeを用いる。ctimeの意味はOS依存で、業務上の確認日時には使用しない。更新日時やサイズだけで内容の一致を判断しない。読取によるアクセス日時の変化は比較しない。CSV以外のメモ等の追加だけでは停止しない。

読取中の更新・差替え・追加・削除・フォルダー変更、読取後の再照合不能を検出した場合、Datasetを返さず停止する。必須CSVの欠損・不正値も従来どおり停止し、欠損をゼロや推定値で補完しない。途中で朝現物在庫CSVが現れた場合も、その場で取り込まず一式の再取込を求める。

## 表示と保存

| 項目 | 内容 |
|---|---|
| INPUT_CHANGED | 対象ファイルの追加・削除・内容・属性等の変更を観測 |
| INPUT_RECHECK_FAILED | 初回内容または読取後の内容・一覧・属性を照合できない |
| source_changed | ファイル一覧の「読取中変更／照合不能」。検証結果を採用しない |
| read_consistency.method | before_after_names_metadata_and_bytes |
| status=stable_observed | 前後の観測で変更を検出しなかった。CSV適合や同一バッチを保証しない |
| status=changed | 変更を検出し取込停止 |
| status=unverifiable | 再照合不能で取込停止 |
| status=not_checked | フォルダー欠損等で検査を実施できなかった |
| atomic_snapshot | 常にfalse |
| changed_files / unverified_files | 検出ファイル、またはフォルダー照合不能の対象 |

診断JSON・HTML・画面詳細に検査方法・結果・制約を表示する。不備があれば計算条件・朝現物在庫の後続診断は未実施とし、正式発行可は常にfalse。ファイル一覧の列・行数・SHA-256は初回に読み取れた内容の観察値であり、変更後の確定値ではない。後から現れた未読CSVはSHA-256・行数を未取得として示す。

通常取込失敗はimport_failedとして記録し、成功した取込や計算として保存しない。GUIでは旧データ・作業明細・確認チェック・参考見通しを無効化する。保存済みの仮指示を再開・照合・正式発行する場合も、保存原本を一時フォルダーで再読する共通検証を通す。

CSV項目・数量式・原文の改行/BOM正規化・既存取込ハッシュ・履歴DB形式は変更しない。旧スナップショットとバックアップは引き続き再読できる。

## 不備発生時の対応と限界

- 自動再試行や新旧データの合成はしない。更新側の処理が完了してから、担当者がCSV一式を改めて取り込む。
- データ責任者は、更新停止した専用の取込用フォルダーに、同じ業務基準・出力世代の一式を用意する。実際の出力完了・公開手順、同一バッチ識別、業務基準日時の保証はブンセン側で確認する。
- 取込前から存在した世代混在は、前後比較だけでは検出できない。観測間に内容・属性・識別が完全に元へ戻った場合や、最終観測後の更新も保証対象外。OS/ファイルシステムの識別や時刻精度にも依存する。
- 初回のバイト列取得より前に更新され、属性・識別でも区別できない場合も検出を保証できない。短時間の書換えで更新日時が変わらない場合があるため、テストでは属性変化を明示したケースと、属性を同一にした初回取得後の内容変化を分けて検証する。
- 取込終了後の元フォルダーを常時監視しない。正式発行では保存原本と出荷条件を再検証するが、元CSVの最新版を自動取得しない。入力が更新された場合は再取込・再計算が必要。
- 全CSVを再読するため読取I/Oと一時メモリーが増える。対象規模での性能・共有フォルダー・同期ソフト・現場PCの受入は未実施。タイムアウトや値の推定で検証を省略しない。

取込検査の成功を、実CSV接続、データ真正性、朝の現物確認、業務ルール承認や正式出荷可の証明として扱わない。
