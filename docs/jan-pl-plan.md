# JAN・物理PL必要補充方式の改修計画

## 確認済みの変更

商品はJAN単位。PL以外の出荷を対象外とし、物理PLのP数をJAN・倉庫別に登録する。神戸30甲×2パレは2物理PL。外部70301/70302の対応は資料間で逆転しているため自動対応しない。

必要補充は確認済みムロオ在庫・既存予測・補充条件だけで計算する。入庫予定/輸送中は対象外で、確認済み0件と表示しない。製造・ブンセン在庫は使用しない。日別推移、入荷前欠品警告、担当者確認、履歴、独立Excel/PDF、概算期限の計算日固定を再利用する。

## 実装

1. requirements.csvを識別子とする独立CSV契約を追加。旧v2の保存原本・計算・再出力は保持。
2. 商品・倉庫別PLマスタの登録/変更履歴と版確認を追加。
3. 必要Pと物理PL切上げ後Pを分離。修正は整数PLのみ。14日計画も同じ倉庫別PL数で16PL/便を検証。
4. 在庫CSVはPDF原本・ハッシュ・転記確認者・基準日時・始業/終業を必須とし、原本証跡を保存。確認済み在庫一覧受払の自動読取・原本表示・確認修正を追加。[PDF読取仕様](pdf-inventory-reader.md)を参照。
5. 架空サンプル、重点テスト、固定日付デモ、Windows検証、PRを作成。

## 未確定

倉庫外部コード、めかぶの期限/積載数、予測の丸め方・注文包含/確認区分、正式補充設定、PDF様式。実資料から未確認値を推定して登録しない。実データと添付Excelをコミットしない。
