# JANマスタCSV・取込順序の改善（0.7.1）

## JAN・倉庫別PLマスタ

「管理・その他」→「JAN・倉庫別PLマスタ」→「CSV取込・ひな形」を開きます。「CSVひな形を保存」で空のひな形、「登録済みを同じCSV形式で出力」で編集用CSVを保存できます。samples/jan-master-template.csvも同じ空ひな形です。

|列|入力内容|
|---|---|
|JAN|半角数字13桁の文字列。Excelで先頭0を落とさない|
|品名|全角英数・日本語可。半角への変換はしない|
|期限種別|賞味期限 / 消費期限|
|製造からの期限日数|確認済みの正整数|
|神戸1PLのP数|神戸の物理1枚に載る確認済みP数（正整数）|
|杉戸1PLのP数|杉戸の物理1枚に載る確認済みP数（正整数）|

UTF-8（BOM可）またはCP932、5MB・1万行まで。列順は任意ですが、この6列をそろえます。内部形式のproduct,name,expiry_type,shelf_life_days,kobe_p_per_pl,sugito_p_per_plも使用可能です。期限の内部値はbest_before/use_byです。既存products.csv/pallets.csvの片方だけをこの一括登録CSVとして採用する機能ではありません。

「CSVを選択」で新規/更新と数量・期限を確認し、担当者・登録変更根拠を入力して「内容を確認して一括登録」を押します。既存の同一JANは更新し、CSVにない商品は削除しません。不備・重複が1行でもあれば全体を停止し、部分登録しません。未確認の数量・期限を補完しません。保存は1トランザクションで行い、原本・ハッシュ・変更前後・担当者・理由を記録します。登録マスタの版や原本が確認中に変わった場合は再読取します。変更後はデータを再取込・再計算してください。

品名の全角英数を拒否する制限は既存の検証にもありませんでした。全角英数を含む品名の画面登録・CSV登録・保持を回帰試験に追加し、数値欄のエラーに日本語の項目名を表示しました。品名の空欄・改行などの制御文字は引き続き拒否します。

## 管理メニュー

従来「管理・履歴」だった補充条件画面を「補充条件」として表示します。取込済みの倉庫・JANを選び、サイクル日・配送日・安全日数・対象日数を変更できます。最初のrequirements.csvは確認済み業務値を用意してください。旧v2商品マスタはメニューから隠します。旧実装・旧履歴は削除しません。

## 在庫PDFの時刻・日付

始業・終業の選択欄を廃止します。2026-11-23にユーザーが確認した方針に基づき、PDFの在庫集計日までの入出庫が反映済みの数量として扱い、翌日から需要を差し引きます。内部のbasis=closingを使用しますが、旧履歴や直接取り込む既存CSVのopening/closingは再解釈しません。

時刻は最初のページのPDF左下作成時刻（秒まで）を初期表示し、HH:MMまたはHH:MM:SSで手修正できます。ページごとの作成日時は原本情報として全件保存します。在庫基準日はPDFの在庫集計日で固定し、在庫基準日時=在庫集計日＋入力時刻（日本時間）です。作成日が翌日でも在庫集計日はずらしません。PDFの作成日時と在庫基準日時を同一視しません。変更前のPDF日時、採用日時、pdf_footer/manualの区分を履歴へ保存します。日中の残需要を時刻から推測する機能ではありません。

## 予測を先に取り込み、後からマスタを登録

予測CSVの未登録JANは警告として一覧表示し、全行を保持して取込・保存できます。未登録商品を削除したり、PL数や期限を仮登録したりしません。保存後に「管理・その他」→「JAN・倉庫別PLマスタ」で登録します。マスタ変更だけで予測の原本を取り込み直す必要はありませんが、計算用のCSV一式は改めて取り込みます。

推奨順序は「予測CSVを先行保存 → JAN CSV登録 → 在庫PDFを確認保存 → 承認済み補充条件を配置 → データを開いて計算 → 修正・正式出力」です。予測の不正値・重複・倉庫対応未設定は引き続き停止します。計算時に未登録JAN・必須在庫・PL・条件の不足があれば停止し、不完全な対象を黙って除いて正式発行しません。

## 検証

`python -m bunsen.tools workflow-demo --output 新規フォルダー` は架空CSV・PDFだけで、マスタ未登録の予測取込、全角品名のCSV登録、PDF時刻の自動表示、集計日翌日からの計算、倉庫別正式Excel/PDF、バックアップ・復元まで実行します。Windows配布版のself-testにも同じ確認を含めます。
