# 業務・計算・帳票仕様（最小版）

## 状態と操作

日常画面は「データ取込→補充計算→不足確認・修正→出荷指示書」の順。日本語・大きめ文字を使用。管理設定は別タブで読み取り表示し、CSV編集・再取込で更新する。

前日は配送先在庫と予測を取り込み、出荷日別に仮指示を発行する。仮指示には常に「乾麺倉庫の当日在庫確認前」、期限・積載の確認状態を記載する。翌日も同じ計算を使用するが独立した参考シナリオであり、今日の確定分を繰り越した連続シミュレーションではない。

当日朝は現物確認済みロット在庫を含むデータ一式を再取込し、再計算して不足を表示。担当者が倉庫・商品ごとのP数量と実ロット（最小版は一明細一ロット）を入力する。担当者名、実ロット・期限・積載の確認操作を経て、発行直前にデータ全体と割当全体を再検証する。未確認条件を確認済みと表示しない。入力変更は確認チェックを解除する。

正式指示は今日だけ。全倉庫同時に検証・発行し、一部だけ発行する機能はない。日付単位の発行番号と連番改訂をSQLiteトランザクションで採番する。同日の再発行は全倉庫分の改訂置換であり追加出荷ではない。旧版も履歴保持する。実出荷済み在庫を扱う追加出荷・取消・排他運用は未対応で、本番化前に設計する。

計算開始時の正式改訂番号を保持し、発行トランザクション内で現行改訂と比較する。不一致なら発行を停止し、再計算・全条件の再確認を求める。発行成功後も計算と確認を無効化する。履歴更新だけで計算時の改訂を更新してはならない。同一ローカルDBの更新競合防止であり、複数端末共有運用の保証ではない。

## 計算

商品ごとのPを整数の基底単位とする。ボール、甲、PLの係数は商品ごとに確認済みマスタで指定する。原則PL、少量品は甲。PL品は整数甲を許し、PL＋残甲で表示する。最小版では混載しない（車両は倉庫・商品専用）。端数積付は禁止。

配送先在庫の基準日は出荷日以前。当該基準日から到着日前日まで毎日の予測を差し引き、到着日までの確認済み輸送中を加える。輸送中の網羅的確認基準日時は在庫と一致し、到着日は在庫基準日より後とする。基準日以前到着分は二重計上の疑いとして取込エラー。

到着日＝出荷日＋倉庫別リードタイム（日、営業日カレンダー未対応）。

必要P＝max(0, 到着日から補充対象日数分の予測合計＋安全在庫P − (確認済み現在庫＋到着日までの確認済み輸送中−到着日前までの予測合計))。

設定のceil/floorに従って商品別のPLまたは甲へ丸める。floorは必要量を満たさない場合があるため根拠を表示する。納期前の欠品リスクも警告する。需要予測は確定注文を含む集約値のみに限定し、別注文CSVは拒否する（二重計上防止）。未確定製造・入庫、代替の自動決定はない。

日別参考表示では、基準日の確認済み在庫を起点に、その日の確認済み輸送中到着数量を加え、当該日の需要予測を引く。今回の補充出荷はこの参考残高に加えない。到着日前日のいずれかの終業予測残高が負なら該当日を警告する。後日の輸送中で既発生の警告を消さない。入庫日の始業予測残高だけで同日需要予測を満たせない場合、入庫時刻と需要発生順は未確認と表示する。これらは予測に基づく参考値で、欠品実績・確定在庫ではない。補充数量は既存の期間集計式を維持する。

朝の不足は商品全体の必要数量と現物在庫の差。正式検証では担当者の割当を倉庫横断でロット別に合計し、数量超過を阻止する。自動で倉庫優先順位を決めない。減量発行は明示された手修正として履歴に残す。

## 期限・積載・履歴

期限は設定の出荷日／到着日を基準に、賞味期限までの日数≧商品別必要残日数とする。容量は商品ごとのP重量(g)と専用車両容量(g)を比較する。重量以外の容積・段積み・混載条件は未対応のため本番では未確定のまま使用不可。必要条件欠落は確認不能として止める。

帳票は倉庫別に種別・番号・改訂・担当者・商品・P・PL＋甲・ロット・賞味期限・出荷日・到着日・データ基準日時・計算根拠・警告を表示。印刷用HTMLをPDF印刷できる。仮指示でも不明値は「未確認」。

再出力時は同日・同種別の現行改訂をDBで照合する。旧版には「旧版・差替え済み — 出荷に使用しない」と現行番号を大きく表示する。最新版にも照合時点を表示し、後日の最新版であることを保証しない。DB未照合のスナップショットから出力する場合は「現行改訂は未照合」と明示する。旧発行履歴を上書きせず、出力用の改訂状態だけを付加する。紙・PDF・保存済みHTMLは自動更新できず、旧版回収は業務側で行う。

SQLiteにはイベント日時、全取込CSV原文とハッシュ、計算根拠、修正、発行時スナップショットを保存。KPI分析画面は未実装。操作開始／発行時刻から試行時間を追えるが、実欠品・緊急便・移送・実績在庫日数の収集は後続段階。
