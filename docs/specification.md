# 現行仕様：ムロオ必要補充方式（v2）

2026-11-14の変更指示・追加訂正を優先。ブンセン在庫確認・朝照合・仮指示からの当日再照合の必須フローを廃止し、ムロオ在庫と需要予測から必要数量を確定する独立アプリとする。特定業務Excelの取込・差込・数式保持は対象外。帳票は計算結果から直接生成する。

## フローと対象

取込→分析→結果→判定/確定→出力。神戸・杉戸を同一画面で独立計算。管理設定・履歴・バックアップ・診断は日常操作と別タブ。入力不備は倉庫・商品・日付・項目・理由で表示し、不足数値を推測や0で埋めない。

新規入力はv2専用契約。旧履歴は原本・番号・改訂を維持して旧方式として閲覧/再出力。旧CSVを新方式へ自動変換しない。新方式で乾麺在庫・出荷ロット・期限・車両在庫割当を検証しない。必要補充指示は実出荷や供給可能性を確定しない。

## 日別計算

- 在庫basis=openingならas_of基準日の日次需要から、closingなら翌日から計算する。
- 到着日=出荷予定日＋商品/倉庫別lead_days。
- 対象末日=到着日＋max(cycle_days,coverage_days)−1日。補充サイクルと明示期間の長い方を保護する。
- 安全在庫P(d)=翌日からsafety_days日分の需要予測合計。0日設定の場合のみ0。
- 補充前残高(d)=前日残高＋確定入庫(d)−需要予測(d)。同日の入庫を需要より先に加える算術定義で、日内の順序は警告する。
- 必要補充P=max(0,max(安全在庫P(d)−補充前残高(d)))。最大値の対象は到着日〜対象末日。
- 必要期間の予測は在庫の計算開始日〜対象末日＋安全日数まで必須。未取得日を0で補完しない。
- 確定入庫は一意なshipment_idを使用し、在庫に反映済みの基準日以前の入庫は拒否。網羅確認日時は在庫日時と一致させる。
- 到着前の負残高は入荷前欠品リスク。今回補充を増やしても過去日の不足は解消しない。負残高は算術的な累積不足であり、実欠品・注文繰越の確定ではない。

旧式の期間総量/丸ごとPL切上げとの差は仕様変更。後日入庫で早い不足を隠さず、商品別甲Pで必要Pを切り上げる。PL数と甲端数を併記し、最小単位P、ボール、甲、PLは商品マスタに従う。

## 予測と設定

既存エンジンのconfirmed/provisional/imputed区分を取り込む。補完/暫定予測を参考分析する場合は担当者が明示選択する。必要期間に未確定予測があれば正式確定を停止する。アプリ内でAI学習、補完、代替値生成はしない。履歴不足時は外部で補完・確認した予測の別一式を選択して取り込む。

設定値はサイクル、配送日数、安全日数、対象日数。商品/倉庫別に管理し、変更値・旧値・理由・担当者・日時・入力原本を履歴保存する。元CSVは上書きせず、変更後は再分析を必須とする。架空サンプル以外の正式値は未確認で、自動初期値を入れない。

## 修正・確定・出力

元需要予測、在庫基準、設定、必要P、換算P、担当者修正P/理由、確定Pを保存。手修正は甲単位・0以上とし、計算値と異なる場合は理由必須。低い修正量の安全在庫未達は警告し、担当者の明示確認に委ねる。担当者名・確認チェック・最新データ再検証・改訂競合検査を正式確定に必須とする。過去出荷日は正式確定不可。将来予定日の指示は確認済み入力で作成できる。

確定は実出荷の登録ではない。変更・未反映編集後の確認使い回しを防ぎ、確定済み結果の変更は再分析から新改訂とする。同日の正式指示は従来どおり全倉庫一括差替え。実出荷後の追加/取消・実績照合は別途必要。

神戸・杉戸ごとにExcel(.xlsx)、日本語PDF、印刷HTMLを直接生成。商品・品名・必要P・換算P・修正P・確定P・PL/甲・出荷予定日/到着日・担当者・番号/改訂・基準日時・設定・警告を表示する。既存ファイルは上書きしない。旧版・復元・架空試用・未確定指示に注意表示を付ける。旧履歴は旧帳票HTMLのまま再出力し、v2へ読み替えない。
