# 予測結果CSVの取込（0.7.0）

日常画面の「予測CSVを取込」から既存予測結果を読み取ります。新しい予測エンジンは追加しません。在庫PDFから確認した現在庫、JAN・倉庫別物理PLマスタ、補充条件と組み合わせて使用します。

## 採用する列

UTF-8（BOM可）のCSV、10MB以下。必須列は次の7列です。列順は任意で、列名の重複は不可です。

|列|扱い|
|---|---|
|JAN|13桁文字列。未登録は警告で先行取込可、計算前に登録|
|倉庫ID|初回は神戸/杉戸への対応を未設定とする|
|予測日|YYYY-MM-DD。倉庫・JAN・日付で一意|
|予測出荷数量（パック）|0以上の整数または有限小数P（96文字以内）|
|予測生成日時|タイムゾーン付き日時。未来の生成日時は採用不可|
|予測区分|通常予測/暫定予測/補完予測|
|予測用途|正式Production予測/参考予測|

「大口込み総出荷数量（パック）」と大口・特売の加減算列は使用しません。製造、入庫、輸送中、予測在庫、他単位の数量も使用せず、欠損の代替列にしません。確定注文の別加算も行いません。元の基本予測に内包されている数量を逆算して取り除く処理はありません。

通常予測かつ正式Production予測を担当者が採用した行だけを確定可能な需要予測として扱います。確定在庫・実績という意味ではありません。暫定/補完/参考予測はその区分を保持し、正式発行できません。未知の区分、欠損、不正値、重複を自動補完・合算しません。「商品・倉庫ID」がある場合はJAN::倉庫IDとの一致を検査し、「予測Run ID」がある場合は空欄・混在を止めます。

## 操作と倉庫対応

1. JAN・倉庫別PLマスタは予測取込後の登録でも構いません。未登録JANを警告表示します。
2. 「予測CSVを取込」で元CSVを選択し、採用列・行数・日付・不備を確認します。
3. 業務で確認した元倉庫コードと神戸/杉戸の対応を指定します。初回の対応は空欄です。両倉庫が一意に指定されるまで保存できません。
4. 担当者を入力して「この予測・倉庫対応を使用して保存」を押し、保存先を選びます。保存先に同名ファイルがある場合は停止します。元CSVは変更しません。
5. 保存したforecast.csvとforecast-review.csvを在庫・補充条件のCSV一式へまとめ、「データを開いて計算」へ進みます。

前回採用した倉庫対応だけを次回画面に表示します。対応変更には再保存が必要で、過去の計算には当時の対応を使用します。外部コードの正解は本実装では固定していません。提供資料のコード差は業務側の確認待ちです。

確認操作は保存ボタンに集約しています。保存成功後は古い計算を無効にし、取り込み直しを促します。担当者が最終数量を確認して確定出力する既存操作は継続します。

## 小数と計算

元の小数Pを正確に保持し、日別合算・安全在庫・不足計算の途中では丸めません。必要Pを求めた後に倉庫別商品マスタの物理1PL数量へ切り上げます。たとえば120.2P＋119.8Pは240P、1PL=240Pなら1PLです。必要Pが240Pをわずかでも上回れば2PLです。倉庫別のPL数・指示Pは整数です。

小数の計算根拠はJSON/CSVでは10進文字列、整数は整数として保存します。Excelの小数根拠は正確さを保つ文字列で出力し、最終出荷P/PLは数値セルです。従来の証跡なし整数CSV契約と旧履歴の意味は変更しません。

## 証跡と再検証

forecast-review.csvに原本バイト列、SHA-256、採用対象範囲、倉庫対応、担当者、変換後forecast.csvのハッシュを保存します。ローカル履歴にも原本・変換内容・対応の変更前後を保存します。取込・再計算・履歴復元時は原本から再生成して比較し、数量や採用列・対応が食い違えば停止します。証跡は暗号署名や本人認証の代わりにはなりません。

必要日の予測不足、在庫の基準日時（PDF画面は集計日反映済み・翌日から需要計算）、補充条件の不足は既存の検証で停止します。CSVを変換できたことだけでは正式発行できません。実CSVの採用・倉庫コード対応・正式業務設定・現場受入の確認完了を意味しません。

架空の固定日付試験:

```powershell
python -m bunsen.tools forecast-demo --output C:\BunsenTrial\forecast-demo
```

0.7.1のJAN CSV登録・後登録フローは[変更手順](master-workflow-fixes.md)を参照してください。未登録JANを含む全行を保存し、マスタ不足が残る計算・正式発行は停止します。
