# 日常画面の簡素化

## 操作

日常は「データを開いて計算 → 数量を確認 → 確定してExcel・PDF出力」の2ボタンを中心に操作します。

- 神戸・杉戸を同じ表に表示。現在庫P・必要P・出荷数量PL・到着日を表示します。
- 商品選択時だけ修正欄が開きます。最新JAN方式は整数物理PL数、旧方式はP数で修正。理由・担当者を保存します。
- 計算根拠は開閉できます。需要予測、安全在庫、基準日時、原本PDFの識別情報を保持し、不備がある場合は自動で開きます。
- マスタ・条件・14日計画・診断・バックアップは「管理・その他」から開きます。「補充出荷」または「履歴」へ戻ると管理タブを隠します。
- 保存担当者名をJANマスタ画面でも共有します。業務上必要な変更根拠は省略しません。

## 取込元

フォルダー選択後に計算します。products.csvとpallets.csvが両方ないJAN方式に限り登録JANマスタを使用します。片方だけある場合は混用せず検証エラーとします。両方あれば選択フォルダーのCSVを使用します。使用元・登録版は計算根拠に表示します。既存の旧方式取込API・履歴の意味は維持します。

## 確認操作

確定チェックボックスと別出力操作を廃止。**確定してExcel・PDF出力**の明示クリックが担当者の最終確認です。保存先キャンセルでは確定しません。コアサービスの確認フラグ・担当者必須・入力再検証・改訂競合検出は維持し、画面からの明示操作中だけ確認フラグを渡し、成功失敗を問わず解除します。

確定保存後のファイル出力が失敗した場合は、同じボタンで保存済み指示を再出力し、新たな改訂を作りません。既存ファイルの上書きは禁止です。部分出力がある場合は別の空フォルダーを選びます。

マスタ・設定・14日計画も保存／確定ボタンを明示確認とし、重複チェックボックスを省きます。欠損・未確認データ・未確定予測・単位違反・未反映修正・閲覧専用状態の発行制限は省きません。参考計算は管理メニューから選択します。

## 検証

自動テストで日常タブの限定、取込と自動計算、整数PL修正、未反映修正の阻止、保存先キャンセル、明示クリックによる確定出力、出力失敗後の重複発行防止、確認フラグの解除を検証します。
