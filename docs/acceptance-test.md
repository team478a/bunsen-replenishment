# 現場受入試験の準備手順

これは試験手順書であり、現場受入完了・実CSV接続完了の記録ではない。自動テストは架空データを使用する。人による受入結果・担当者・実施日・不備は別途記入する。

## 実施前

- 業務設定、確認者、現物在庫手順、期限・積載条件を責任者が確定する。未確定事項は`open-questions.md`参照。
- 実データ・既存DBを上書きしない試験環境を用意する。試験で発行した帳票は実出荷に使用しない。
- サンプル日は2026-11-09。UIの正式発行は本日のみなので、日付が異なる場合は固定日付の自動テストと`python -m bunsen.demo`でロジックを検証する。実日付での受入には責任者が確認した試験データを用意する。

## 仮指示から翌朝への引継ぎ

| 操作 | 期待結果 | 現場での結果 |
|---|---|---|
| `samples/before_morning`を取込・計算 | 神戸／杉戸240Pの推奨、朝現物在庫は未確認 | 未実施 |
| 仮指示を発行してアプリ終了・再起動 | 履歴に仮番号が残る | 未実施 |
| 履歴から最新の仮指示を再開 | 数量・ロットが復元され、担当者・確認は空。保存原本の表示 | 未実施 |
| 朝データなしで正式発行を試す | 現物在庫未確認等により停止 | 未実施 |
| `samples/morning`を再取込・再計算 | 元数量240Pを保持し、全体不足240Pを表示。変更区分に乾麺現物在庫 | 未実施 |
| 両倉庫にL001を指定して240Pのまま発行 | ロット在庫超過で停止 | 未実施 |
| 各倉庫120Pへ修正・再確認・正式発行 | 正式帳票と元仮番号・数量比較を保存 | 未実施 |
| 旧版の仮指示・正式履歴の再開を試す | 再開不可。再出力のみ可能 | 未実施 |

## 異常・変更時

| 操作 | 期待結果 | 現場での結果 |
|---|---|---|
| 再開中の朝CSVに欠損を入れて取込 | 旧データでの発行不可。手修正は保留し、修正後の再取込で引継ぐ | 未実施 |
| 数量を未反映のまま再計算・取込 | 未反映入力を知らせて停止 | 未実施 |
| 予測・配送設定を変更し再計算 | 手修正保持、現在推奨・到着日を更新。自動で再配分しない | 未実施 |
| 商品を追加・削除したデータで照合 | 対象商品・倉庫を示し停止。指示明細を自動追加・削除しない | 未実施 |
| 別画面で参照元仮指示を更新 | 古い参照元での発行停止。最新仮指示の再開・再確認を要求 | 未実施 |
| 再開中に新しい仮指示を発行 | 新しい番号が再開元になり、旧元番号との関係も履歴に残る | 未実施 |

## 別途必要な受入

実CSVのコード・単位・確認日時・網羅性、実倉庫の不足判断、実ロット期限、車両の重量以外の積付条件、実プリンター、日本語PDFのページ割り・改訂回収、権限、バックアップ・復旧は未実施。自動テスト成功でこれらを承認済みと扱わない。
