# 補充条件画面の入力方法（0.7.2）

## 最初にすること

「データを開いて条件を表示」で、在庫・需要予測・商品PLマスタ・requirements.csvをそろえたフォルダーを選びます。この画面は取り込んだ補充条件の確認・変更用です。最初のrequirements.csvは管理担当者が確認済み業務値で準備してください。データ未取込・取込失敗時は数値を空欄にし、入力と保存を止めます。数値の初期値や本番値を自動決定しません。

「対象の倉庫・商品」には倉庫名・JAN・品名を表示します。変更したい行を選択してください。同じ商品でも神戸と杉戸は別々の条件です。

## 各欄に入れる内容

|画面の項目|意味|入力条件|
|---|---|---|
|補充する間隔（日）|何日ごとに補充するか|1以上の整数|
|到着までの日数（日）|出荷日からムロオ到着までの暦日数（休日を含む）|0以上の整数。0は当日到着|
|安全在庫の日数（日）|各日の翌日から何日分の予測需要を残すか|0以上の整数。0は安全在庫なし|
|補充でまかなう日数（日）|到着日から何日分を補充対象にするか|1以上の整数|
|変更理由|何を、なぜ変更するか、確認した根拠|必須|
|設定を確認した担当者|変更を確認した担当者名|必須|

実際の補充対象期間は「補充する間隔」と「補充でまかなう日数」の大きい方です。安全在庫は日別予測から計算し、固定のP数を入力する欄ではありません。補充サイクル、配送条件、必要在庫水準は業務側の確認済み値を使います。画像やサンプルで見た1・1・2・14を正式値としてそのまま採用しないでください。

## 保存と再計算

「この条件を保存（再計算が必要）」で、選択した倉庫・商品だけを変更します。変更前後・理由・担当者を履歴へ保存し、元CSVは上書きしません。保存後も選択対象を維持します。「補充出荷」へ戻り「再計算」で数量を確認してください。以前の計算をそのまま確定できません。

JAN方式の商品期限・PL数量は「JAN・倉庫別PLマスタ」で設定します。補充条件画面には旧v2の期限欄、履歴一覧、内部JSONを混在させません。旧機能・保存済み履歴は保持し、帳票の再出力は「履歴」から行います。
