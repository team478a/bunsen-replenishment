# 補充条件画面の入力方法（0.7.6）

神戸・杉戸を同じ画面に並べ、倉庫別に4項目を入力します。到着までの日数はそれぞれの倉庫で設定してください。各倉庫では全商品に共通です。商品選択や条件CSVは不要で、データ未取込でも保存できます。設定理由と担当者を入力して「倉庫別の条件を保存」を押してください。

倉庫番号KOBE＝ムロオ神戸、SUGITO＝ムロオ杉戸はアプリ内の識別です。予測CSVの倉庫番号は、予測取込で担当者が保存した対応だけを各倉庫の見出しに表示します。未登録の番号は推定しません。

## 各欄に入れる内容

|画面の項目|意味|入力条件|
|---|---|---|
|補充する間隔（日）|何日ごとに補充するか|1以上の整数|
|到着までの日数（日）|出荷日からムロオ到着までの暦日数（休日を含む）|0以上の整数。0は当日到着|
|安全在庫の日数（日）|各日の翌日から何日分の予測需要を残すか|0以上の整数。0は安全在庫なし|
|補充でまかなう日数（日）|到着日から何日分を補充対象にするか|1以上の整数|
|変更理由|何を、なぜ変更するか、確認した根拠|必須|
|設定を確認した担当者|変更を確認した担当者名|必須|

実際の補充対象期間は「補充する間隔」と「補充でまかなう日数」の大きい方です。安全在庫は日別予測から計算し、固定のP数を入力する欄ではありません。補充サイクル、配送条件、必要在庫水準は業務側の確認済み値を使います。画像やサンプルで見た1・1・2・14を正式値としてそのまま採用しないでください。

## 保存と適用

保存した倉庫別条件は次回の在庫・予測取込から、該当倉庫の全商品へ適用します。商品別の設定操作はありません。変更前後・設定理由・担当者・保存日時・版をローカル履歴に保存し、再起動後も表示します。条件変更後はデータを再取込・再計算してください。古い条件の計算結果や配送計画は正式確定できません。

新しい画面で取り込むときは、保存済みの倉庫別条件から内部の計算行を生成するため、requirements.csvの用意は不要です。既存のrequirements.csvは変更・削除せず、画面の倉庫別条件を使うモードでは採用しません。使用した条件と版は取込原本・計算・確定履歴に保存します。商品マスタ・在庫・予測の不足は引き続き停止します。

内部のcommon-settings.csvは保存条件の証跡で、ユーザーが作成する入力ファイルではありません。条件と計算行の一致・保存版を再検証します。旧CSV/旧履歴の意味は変えず、既存のAPI互換読取を保持します。復元した履歴は閲覧専用です。

## 以前の共通条件がある場合

旧共通条件は画面の説明欄と履歴に残しますが、新しい倉庫別欄へ自動適用しません。両倉庫の実際の条件を入力して一度保存してください。片方でも空欄・不正値があれば保存・新規計算を止めます。以前発行した指示は当時の条件・到着日で再出力できます。

詳細な変更範囲と検証は[倉庫別条件への改修](warehouse-settings.md)を参照。
