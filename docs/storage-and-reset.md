# データ保存先とJANマスタ初期化（0.7.5）

## 旧版で別の展開先にも同じマスタが表示された理由

0.7.4までの標準GUIは、アプリの展開先に関係なく `%LOCALAPPDATA%/BunsenReplenishment/history.db` を開いていた。同じWindowsユーザーでは別ディレクトリのEXEも同じDBを参照した。マスタ・補充条件・予測の倉庫対応・履歴はこのDBに保存されていた。別ディレクトリへデータをコピー・移行する処理によるものではない。

起動処理、保存先切替、ServiceのDB生成、バックアップ復元、配布リソースを調査した。標準起動で他ディレクトリを探索したり、旧マスタを自動コピーしたり、ネットワークから同期する処理はない。一方、共通保存先を使う従来仕様の説明と、検証用の初期化手段が不足していた。

## 0.7.5からの標準保存先

標準GUIは **EXEのあるフォルダーの `data/history.db`** を使用する。ソース起動はリポジトリ直下の `data`。作業ディレクトリには依存しない。画面上部に現在の保存先を常時表示する。

- 新しいZIPを別フォルダーへ展開すると、空の独立データで起動する。配布ZIPに業務DBは含めない。
- 同じフォルダーのアプリを開き直すと、その `data` 内のデータを再使用する。
- `data` も含めたフォルダー全体をコピーした場合は、そのコピー内のデータを開く。
- 保存先が書込不可・不正なら起動を停止する。旧共有先への自動フォールバックや移行はしない。
- 旧版の共有データは変更・削除しない。必要な場合だけ以下のメニューで明示的に開く。
- `--data-dir` / `--trial-kit` は明示指定として引き続き優先する。旧履歴用LegacyApp内部の既定値は互換性のため変更しない。

## 検証で使う操作

### 現在のJANマスタ一覧だけを空にする

「管理・その他」→「JAN・倉庫別PLマスタ」→ **「全JANマスタを初期化（バックアップを保存）」**。

担当者と理由を入力し、現在のデータフォルダー外へ新規バックアップZIPを保存する。検証済みバックアップの保存に成功した場合だけ、対象外の商品も含めて現在の一覧を空にする。同じJANを新規登録し直せる。キャンセル・保存失敗・他画面からのマスタ変更・閲覧専用では実行しない。

過去の出荷指示、取込原本、変更前のマスタと初期化理由は履歴として保持する。共通補充条件・予測対応も残す。変更後は再取込・再計算が必要。外部に保存済みのCSV自体は変えないため、そのCSVにマスタが含まれる場合、明示的に取り込めばCSVの内容を読む。

「選択JANを対象外にする（削除）」は補充対象から外す操作で、一覧行と復帰機能を保持する。「全JANマスタを初期化」は現在の一覧全体を空にする操作で、過去履歴の物理削除ではない。

### マスタ・設定・履歴を一切引き継がず検証する

「管理・その他」→ **「データ保存先・空のデータで検証」** →「空のデータフォルダーを新規作成して開く」。親フォルダーを選ぶと、重複しない新規フォルダーを作る。旧データを削除・コピーせず、マスタ、共通条件、予測対応、発行履歴のない状態へ切り替える。未保存入力も引き継がない。

同画面の「既存データフォルダーを選んで開く」は、`history.db` を読み取り専用で事前検証してから開く。「旧版の共有データを明示的に開く」は、旧共有先を利用者の操作で開く。復元履歴は閲覧専用のまま。

切替先の記憶・自動再選択はしない。次回の標準起動はEXE横の `data`。別の保存先を継続する場合はメニューで再選択するか `--data-dir` を指定する。履歴番号はデータフォルダーごとに独立するので、検証用と実運用の保存先を混同しない。

## 確認と限界

架空データで展開先A/Bの独立、Aの再起動保持、旧共有DBのハッシュ不変、明示的な旧データ参照、初期化のバックアップ復元、同JANの再登録、旧正式指示の保持、画面の残存データ解消、失敗時の停止を自動検証する。利用者の実データを開いたり初期化したりしない。現場端末での手操作受入は別途必要。
