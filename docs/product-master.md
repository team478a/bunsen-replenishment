# 画面での商品マスタ登録・編集

## 調査と実装方針（2026-11-16）

main e05e173はproducts.csv取込と期限だけの画面変更に対応。商品追加は全倉庫の商品行が必須のCSV検証に依存しており、単純に商品行を増やすと保存自体が止まる。補充データと独立した確認済み商品マスタを既存events表へ保存し、既存DB/帳票/バックアップを保持する。

1. CSV未取込でも商品を追加/編集する管理タブを追加する。商品コード・名称・P/ボール/甲/PL換算・出荷単位・賞味/消費期限区分・製造からの日数を入力。換算/期限の初期値を推測しない。1甲/1PLのP数を表示し、担当者・理由・明示確認で保存する。
2. 商品コードを識別子として保持し、既存コードは編集で変更しない。コード変更は別商品として登録し、旧履歴を改名/削除しない。重複追加を拒否する。元CSVからの転記は選択商品をフォームへ表示するだけで、自動上書きや確認済み保存をしない。
3. 登録マスタは変更前後・全商品スナップショット・担当者・理由・日時とともにローカルeventsへ保存。版はイベントIDで識別し、同時編集時の古い版を拒否する。復元は閲覧/CSV新規出力のみ。
4. 日常操作に「登録商品マスタを使う」を追加。未選択なら従来CSV方式。選択時は登録全商品をproducts.csv原本として明示適用し、物理products.csvを読まずに他4CSVを従来通り安定読取・検証する。登録0件は停止。版と原本を計算/発行/計画に保存する。
5. 新商品に必要な神戸/杉戸の在庫・補充条件・日別予測・確定入庫の網羅確認を整備するまで計算/正式確定を停止する。欠損を0や既存商品の設定で埋めない。画面登録だけで在庫行や予測を自動生成しない。
6. 商品マスタ変更後は作業中の計算/確認を解除。登録マスタ利用中は再取込を求める。他画面での変更も発行/計画確定時の版照合で停止する。過去帳票・確定済み計画の閲覧は元の値を保持する。
7. products.csvを新規ファイルへ出力できる。既存ファイルや入力CSVは上書きしない。

## 入力契約・制限

換算数と期限日数は既存契約と同じ正整数、出荷単位はPL/CASE、期限区分はbest_before/use_by。商品コード/名称は空欄不可。コードはUIの区切り文字に使う縦棒および制御文字を使用できない。商品コードの自動採番・削除・単位換算値の全商品共通化はしない。

画面登録には全項目の確認が必要。旧CSVに期限がない場合は転記フォームで未整備として表示し、確認済み日数を入力する。既存CSV方式の旧ヘッダー/期限未整備の扱いは変更しない。

実在庫・予測・確定入庫は引き続きCSV連携。ブンセン在庫・製造実績・実ロットは導入しない。業務上の正式な換算/期限/権限の承認と実CSV照合は別途必要。

## 検証

単独新規登録、再起動、変更履歴、重複/欠損/不正値、同時編集、登録マスタで4CSV取込、新商品の不足対象表示、変更後の再計算/確認、旧帳票保持、CSV非上書き、復元閲覧専用、UI操作、Windows配布を検証する。
