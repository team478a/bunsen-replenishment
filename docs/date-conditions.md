# 在庫・予測・出荷日の日付条件（現行0.7.10）

2026-11-25に現行コードと固定日付テストで確認した条件です。出力済みPDFを入力検査へ含めて停止する既知エラーは0.7.9で修正済みで、日付変更後のフォルダー再選択・再計算も正常動作を確認しました。以下の日付・予測条件による停止は、その不具合と区別します。

## 日付を変更した場合

出荷日は `YYYY-MM-DD` で入力します。変更すると、変更前の計算結果・確定確認は無効になります。「再計算」を押し、到着日・必要量を再確認してください。入力データや設定も変更した場合は「データを開いて計算」で再取込します。古い数量修正は新しい出荷日に自動適用されません。

同じ入力データでも、後ろの日付へ変更すれば予測の必要最終日も後ろへ延びます。出荷日を早めれば、在庫や予測の基準日が出荷日より未来になる場合があります。日付だけ変更すれば常に計算できる仕様ではありません。

## ムロオの在庫基準日

- 新規PDF取込では、PDFの**在庫集計日まで反映済み**の在庫として扱い、需要予測を差し引く初日は**在庫集計日の翌日**です。
- PDF作成日は在庫集計日と別です。翌日作成のPDFでも在庫集計日は変更しません。最初のページの作成時刻を基準時刻の初期表示とし、必要なら担当者が手修正します。
- 在庫集計日は出荷日以前でなければなりません。加えて、在庫集計日の翌日が到着日以前であることが必要です。
- 特に到着まで0日の倉庫で、出荷日と同じ集計日のPDFを使うと、翌日からの需要と当日到着の基準が合わず停止します。この場合は業務に合う原本・配送条件を確認してください。回避のために在庫日付を改ざんしないでください。
- 古い在庫基準でも、途中の日別予測がそろえば計算できる場合があります。経過日数に上限を設ける鮮度判定は未実装です。古い在庫を最新の実在庫と表示したり、実際の在庫を保証したりするものではありません。

旧CSV・旧履歴の `opening` は基準日から、`closing` は翌日から差し引く当時の意味を維持します。旧データの区分を、新規PDFの方式へ自動で読み替えません。

## 必要な予測期間

倉庫別・JAN別に、次の期間の日別予測が連続して必要です。

```
到着日 ＝ 出荷日 ＋ その倉庫の到着までの日数
補充対象日数 ＝ max(補充する間隔, 補充でまかなう日数)
補充対象末日 ＝ 到着日 ＋ 補充対象日数 − 1日
必要予測初日 ＝ 在庫集計日 ＋ 1日（新規PDF）
必要予測末日 ＝ 補充対象末日 ＋ 安全在庫の日数
```

**出荷日からの予測だけでは足りません。** 在庫基準翌日から出荷前日までに需要があれば、その日分も必要です。欠損日はゼロとせず停止します。需要0の日は、確認済み入力として0の行が必要です。

例（架空設定であり正式値ではありません）:

- 在庫集計日: 11月24日
- 出荷日: 11月25日
- 到着までの日数: 2日 → 到着日11月27日
- 補充間隔1日・まかなう日数3日 → 対象末日11月29日
- 安全在庫2日 → **11月25日〜12月1日**の予測が必要

14日配送計画は各配送候補日で同じ検証をするため、単に14日分ではなく、リードタイム・補充対象期間・安全在庫に応じた先の日付まで必要になる場合があります。

## 予測生成日時と正式発行

- 在庫集計日と予測生成日が同じ日である必要はありません。
- 予測生成日時と在庫基準日時は、読取・確認時点より未来の日時にはできません。
- 使用する予測の生成日が出荷日より未来の場合も停止します。予測の対象日と生成日時を区別してください。
- 通常・正式Production予測を採用した結果のみ正式発行できます。暫定・補完・参考予測を使用した計算は正式確定できません。
- 現行の必要補充指示は、本日以降の出荷日で、必要条件を満たせば正式確定できます。過去日は正式確定できません。
- 乾麺倉庫の数量照合は別の条件です。実在庫の基準日と指示の出荷日が違えば「基準日違い・確認不能」になります。Excelにある入力時刻やファイル名だけで基準日を確定しません。

## エラー時の切り分け

1. 出荷日を正しい形式で入力し、再計算したか。
2. 在庫集計日が出荷日より未来になっていないか。0日配送と同日集計の組合せになっていないか。
3. 在庫集計日翌日から必要予測末日まで、倉庫・JANごとの行が連続しているか。
4. 予測生成日時、未確定予測、過去日発行の制限に該当しないか。
5. 数量・設定の未反映、原本変更、既存出力ファイルなど、日付以外のエラーではないか。

解決しなければ、変更前後の出荷日、エラー全文、在庫集計日、予測の最初/最後の対象日、倉庫別条件を確認します。日付をずらしたり欠損を0にして回避したりしないでください。
