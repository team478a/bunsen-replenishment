# 乾麺倉庫の実在庫取込（0.7.7）

## 目的・範囲

ムロオへの出荷前の仮置き倉庫に実在する数量を取り込み、今回の神戸・杉戸への指示数量を商品ごとに合算して照合する。ムロオ側の必要補充計算には加減算しない。旧ロット別在庫・朝照合・製造実績からの推定は再利用しない。

今回の入口はCSV。利用者よりCSVで用意可能と確認済み。実際の元CSVの列対応は未確認で、以下は仮の連携仕様。実データ接続完了とは扱わない。CSVひな形と架空サンプルを同梱する。

## CSVと確認情報

列は `JAN,実在庫P,他出荷向け取置P`。JANは半角13桁。数量は確認済みの0以上の整数P。取置0も明示入力が必要。重複JAN、空欄、不正値、取置が実在庫を超える行は全件停止する。UTF-8/BOMまたはCP932、5MB・1万行以下。

画面で基準日時（日本時間、年月日と時刻）と確認者を入力し、明示的な保存操作で確認済み実在庫として保存する。空欄を現在時刻で埋めない。未来日時は停止。CSV原本・ハッシュ・行・基準日時・確認者・保存時刻・版をローカル履歴に保存し、読取後に元ファイルが変わった場合や保存版の競合は停止する。

未登録JANは警告表示し、取込自体は保存可能。計算対象JANが在庫CSVにない場合は0ではなく確認不能。商品名は現在の確認済みマスタから表示し、推測しない。

## 数量照合

- 使用可能P＝実在庫P−他出荷向け取置P。取置は今回照合する指示を除く、他の出荷向け確保分を確認して入力する。
- 今回指示P＝現画面の神戸・杉戸への手修正後の指示数量PをJAN別に合算。
- 不足P＝max(0,今回指示P−使用可能P)。PL切上げ後の数量で照合し、倉庫ごとに同じ在庫を別々に使わない。
- 基準日が出荷日と異なる、該当JANがない場合は確認不能。必要量Pと指示量Pを分けて表示する。
- 不足商品の配分や出荷数量は自動変更しない。担当者が通常画面でPL数量・理由を修正してから、照合画面を開き直す。
- 保存する照合履歴は、元計算の識別、出荷日、両倉庫の指示数量、実在庫版、照合結果を持つ不変スナップショット。画面を開くたび最新数量で再照合し、過去の照合結果を使い回さない。

「数量上は充足」は照合時点の数量比較。出荷予約・実出荷登録ではない。複数指示間の自動引当、取置の自動増減、実ロット・実期限適合性の保証、製造数量算出は対象外。今回の入口追加では既存の正式必要補充指示の発行条件は変更しない。実在庫照合を正式出荷の必須条件にする運用や予約管理は別の仕様決定が必要。

## 実装・検証計画

1. CSV検証・保存と、読み取り専用復元を含む履歴検証を追加。
2. 日常画面の別行に取込・照合の入口を追加。ひな形・読取結果・基準日時・確認者・JAN別照合を表示。
3. 欠損と0、重複、不正値、取置、神戸杉戸合算、PL切上げ後の不足、日付違い、修正後の再照合、版競合、原本改変、バックアップ復元を架空データでテスト。
4. Windows配布版の固定日付self-testに取込・照合経路を追加する。実在庫は必要補充数量を変えないことを確認。


## 0.7.10 Excel直接取込（2026-11-24確認）

ユーザー確認済み: 実在庫数はパック数で、他の出荷向け取置を差し引いた出荷可能数量。同じJANの複数品番は合算する。今後の品番管理への変更は未確定で、今回の照合キーはJANを維持する。

- 任意の.xlsxファイルから「実在庫」シートを読む。品番コード・品番名・規格・JANCD・1ケースの個数・1ボールの個数・1パレットのケース数・実在庫数・荷姿換算・状態・入力時刻の11列が対象。CSV方式も保持し、Excel本体や追加の常駐サービスは不要。
- JANCDで照合し、「入力済み」の整数パック数を合算。品番・元行・品名・規格・入力値・状態・時刻・荷姿情報を原本とともに保存する。重複品番は二重入力の疑いとして停止する。
- 「未入力」の空欄を0にしない。同じJANに未入力が残る場合、入力済み小計は参考表示するが、出荷可能合計と不足Pは未確認。数量0の入力済み行は確認済み0として扱う。状態と数量の入力有無の矛盾は停止する。
- 使用可能PはExcelの出荷可能合計をそのまま使用する。現物総数と取置内訳は不明であり、取置0へ置き換えず、再度差し引かない。従来CSVの実在庫P−他出荷向け取置Pと履歴の意味を変更しない。
- 元帳票のケース/ボール/パレット情報と「荷姿換算」は証跡として保持し、数量の再乗算、物理PLマスタの自動更新、P表記からのパレット推定には使用しない。ムロオ向けPLは既存の倉庫別マスタから計算する。
- 入力時刻だけでは在庫基準日を確定できない。ファイル名の日付や現在日時を正式値にせず、基準日時を日本時間で担当者が入力する。ファイル内の日時は参考情報として保持。
- 数式セルは計算せず停止し、式のキャッシュを確認済み数量として使用しない。5MB、展開後40MB、商品1万行まで。構造異常・不正数量・JAN桁不足・原本変更・版競合は保存停止。未入力は保存可能だが、そのJANの照合は確認不能。
- Excel原本・ハッシュ・形式版・数量の意味・JAN合算と元明細を履歴へ保存し、保存/バックアップ復元時に原本を再解析して一致を検証する。旧CSV履歴も従来の意味で検証する。

検証計画: 架空Excelによる直接取込→JAN合算→神戸/杉戸合算照合→履歴→バックアップ復元、元の必要補充量不変、未入力/0、部分入力JAN、不正/数式/重複品番、原本改変、入力日未推定、CSV互換を自動テストする。実業務原本はローカル確認に限定しコミットしない。
