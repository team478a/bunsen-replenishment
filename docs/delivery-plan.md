# 14日間配送計画と概算期限（2026-11-16）

## 調査・改修方針

main 5f520ebには新方式の日別補充計算・CSV検証・設定変更履歴・直接Excel/PDFがある。14日配送便生成は未実装で、旧outlookは補充前残高の参考表示のみ。これを配送最適化済みとは扱わない。

既存の確認済み入力、商品別換算、日別必要量計算を再利用する。新規配送計画は既存の指示書と別のイベントとして原本・基準日時・設定・計算日時・確認者を保存する。旧履歴・DBスキーマを変更しない。

## 商品マスタ

products.csvの既存列にexpiry_type（best_before=賞味期限、use_by=消費期限）、shelf_life_days（製造日からの正整数日数）をconfirmed直前に追加できる。旧ヘッダーは既存補充計算用に引き続き受理するが、14日計画では期限項目がない商品を一覧にして停止する。1PLのP数は既存のp_per_ball×balls_per_case×cases_per_pl。別の固定値を設けない。

管理画面で商品ごとに期限種別・日数を確認し、理由・担当者を付けて原本のコピーと履歴へ保存する。入力CSVを上書きしない。

## ルール計算

- 計画開始日から14日間の出荷予定を作成。各配送先は独立便とする。営業日・休日・便数上限は未承認なので自動仮定しない。
- 毎日、既存補充計算と同じmax(サイクル,対象日数)・安全日数・配送日数を使う。既に作成した計画入庫を別の予測情報として加味し、同じ不足を重複補充しない。確定入庫CSVへ計画入庫を書き戻さない。
- 正の補充を作成した後は設定サイクル間隔を空ける。甲に切り上げ、1PLは1商品のみ。甲端数のパレットも1枠を占有し、他商品と混載しない。1便最大16枠。必要なら同日同倉庫に複数便を作成する。
- 決定的な日付順・商品コード順の実行可能なルール計画。便数や費用の大域最適解を保証しない。計画対象14日より後の入荷や安全在庫の評価には追加日数分の予測が必要。不足をゼロ補完しない。
- 計画計算実行日時をJSTで保存し、その日付を全配送の仮製造日として固定。概算期限=仮製造日+shelf_life_days。出荷日・到着日を仮製造日に置換しない。残存日数は概算期限との差（当日0日）。
- 期限評価は参考。負の残存日数を警告し、追加補充合計と最初の計画入荷から概算期限までの予測需要を比較する。期間内予測が足りなければ確認不能とし、過大数量を捏造しない。既存在庫から期限切れ数量や廃棄数を算出しない。

## 保存・確認・出力

新規計算は別IDで保存。計算後の画面変更は確認を解除する。正式配送予定の確認には担当者・明示チェック・確認済み予測を必須とし、保存原本から同じ計算日時で再計算する。正式配送予定は実出荷・実期限の保証や既存正式出荷指示書の発行ではない。

倉庫別Excel/PDF/HTMLとJSONで計画・便・参考期限・警告を出力する。履歴から同じ計算日で再出力し、試用・復元表示を維持する。実製造日・製造数量・ロット・ブンセン在庫・FEFO・実ロット廃棄・新LL連携は対象外。

## 検証・未確定事項

期限固定、種別/日数欠損、商品別換算、16PL境界・分便・商品混載禁止、確定/計画入庫の二重計上、14日残高、期限超過/過大の参考警告、予測欠損/暫定の正式停止、再起動/再検証/バックアップ互換をテストする。

実CSV接続・正式設定・休日/締切・同日複数便の運用可否・部分パレット積付・実プリンターは業務承認が必要。制約に実重量/容積は含めず、16PL枠を検査したことと区別する。
