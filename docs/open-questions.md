# 現行方式で確認が必要な事項

## 運用前の必須確認

- 実CSVの列・文字コード・商品/倉庫コードと仮契約v2の対応、データ責任者・更新頻度・網羅性。
- ムロオ在庫のopening/closing基準と日別予測/入庫の切時刻。日中途中の現在庫を日次全量へ重ねない対応。
- 商品ごとのP/ボール/甲/PL換算、サイクル・配送日数・安全日数・対象日数の正式値と変更権限。サンプル値を正式値にしない。
- 対象日数=max(サイクル,対象日数)、安全在庫=翌日から安全日数分の予測合計という実装上の定義と、実業務での解釈の合意。
- 確定入庫の一意なID、在庫反映済みと未反映の境界、網羅確認、予測への確定注文包含、confirmed/provisional/imputedの確認責任。
- 手修正で必要数量を下回る場合の承認・理由・判断権限。今回の正式確定は担当者の明示確認で、供給可能性や実出荷の保証ではない。
- 現場PC・プリンター・Excel/PDF表示、日本語フォント、長い品名/理由、多品目でのページ割り、署名・本番配布承認。
- バックアップ保管・保存年限・障害後の本番復帰、失われた出荷/改訂との照合。復元は引き続き閲覧専用。

## 今回の対象外・後続

実出荷実績の取込、実倉庫のロット/期限/積載・供給在庫管理、追加出荷/取消、休日/締時刻、倉庫間移動や欠品/緊急補充/KPI実績、権限認証、共有DB、予測学習は未実装・未確認。特定の業務Excelの取込/差込は今回の要件から除外済みで、テンプレート提供待ちの作業ではない。

ブンセン在庫確認と朝照合は新方式の必須条件ではない。旧資料の当該条件は旧履歴の解釈用であり、新しい日常操作に適用しない。データ不備の整備は業務側が行い、アプリは推測・ゼロ補完しない。
