# ブンセン側で決定・整備が必要な事項

以下はサンプル値で承認済み業務ルールではない。本番使用前に責任者・承認日・値を記録する。

- 実CSVの列・文字コード・商品／倉庫コード、取込時刻、各データの確認者と網羅性保証。
- 神戸／杉戸の配送リードタイム、休日・締切、補充対象日数、安全在庫、ceil/floor、PL/甲の適用商品。
- 不足時の倉庫優先順位・比例配分。初期版は自動配分せず担当者が全体在庫内で指定する。
- 予測への確定注文包含保証、予測更新頻度、許容鮮度。初期版はincluded宣言のみ許可する。
- 出荷許容期限の基準日・商品別残日数、ロット選択、先入先出、複数ロット分割の運用承認。担当者による手動分割機能は第3段階で実装するが、倉庫優先配分・自動ロット選択・同一PLへの異ロット積付条件は未承認。
- 商品重量、車両容量、容積・高さ・段積み、PL配置、混載・端数積付。初期例は専用便・重量制約のみ。
- 朝の全ロット現物確認手順（JST午前中を仮採用）、ゼロ在庫の記録方法、確認者の権限。
- 正式発行権限・差替え、実出荷後の追加出荷・取消、複数担当者とDB共有、旧紙帳票の回収。
- PDF自動生成、帳票レイアウト承認、署名付きWindows配布と更新方式、バックアップの保管先・保存年限・別媒体コピー・復旧責任者。第5段階は新規フォルダーへの閲覧専用復元まで。本番復帰はバックアップ後の出荷・改訂との照合、失われた履歴と発行番号の扱いを業務側で決定する。
- 当日確定分と翌日計画の連続シミュレーション、4〜7日／8〜14日の参考表示。
- KPI実績入力：欠品・緊急補充・倉庫間移送・過剰在庫日数の定義とデータ責任者。

Windows x64の署名なし試用ZIP・GUI／復旧exeは第6段階で作成する。署名証明書・発行元、本番配布の承認、Windows 10/11のクリーンな現場PCでの受入、インストーラー・自動更新は引き続き未確定・未実施。

第7段階では仮契約の取込前診断と実CSV対応表のひな形を作成する。実CSV・仕様書は未提供で、実側のファイル・列・単位・文字コード・変換は未確認。ひな形の記入・診断成功を実接続や業務承認の完了と扱わない。

データ不備の修正はブンセン側で行う。アプリは不備対象を示し、推測で補わない。

第8段階の受入キットは架空CSVの操作試験準備のみ。現場担当者・実施日・端末・プリンター・結果/証拠の保存先・判定責任者は未確定で、受入記録は全件未実施として開始する。実CSVは引き続き未提供。
