# 在庫PDF自動読取・確認

## 対応範囲

Windows単体で、文字情報を持つムロオ「在庫一覧受払」PDFを読み取る。クラウドやAI API、OCRサービスは不要。確認済みの神戸支店・杉戸営業所のレイアウトに限定し、画像スキャンや別の帳票は読取不能として停止する。文字・表位置の抽出にpdfplumber、アプリ内原本表示にPDFiumを使用。依存版をrequirements-runtime/buildで固定する。

0.7.1の在庫基準は「在庫集計日」とPDF作成時刻を初期表示した基準時刻。始業・終業の選択は廃止し、集計日まで反映済み、翌日から需要を差し引く。帳票作成日時は参考情報として別保存し、深夜に翌日作成された帳票でも集計日を翌日へずらさない。各ページで数秒異なる作成時刻も記録する。

## 日常操作

1. JAN・倉庫別物理PLマスタを確認登録する。
2. 補充出荷画面の「在庫PDFを読み取る」を開く。
3. 神戸・杉戸のPDFを選択する。ZIPの場合は一覧から対象日のPDFを1件選択する。全日分を合算したり、ファイル名だけで倉庫や最新日を決めたりしない。
4. 帳票内の営業所名・集計日・作成日時と、各商品の現在庫を確認する。「原本を見る」でページを切り替えて確認できる。
5. 倉庫ごとにPDF左下の最初のページの時刻を初期表示。必要ならHH:MMまたはHH:MM:SSで修正する。在庫集計日と合わせ日本時間として保存。翌日作成でも集計日を変更しない。内部basis=closingとし、翌日から日別需要を差し引く。PDF作成日時全件と手修正区分を別保存する。
6. ケース・バラの空欄は初期状態で未確認。帳票上の意味を確認した場合だけ「バラの空欄は0」または「ケース・バラの空欄は0」を選択する。ルールは今回のPDF単位で保存し、別PDFの読取時は未確認へ戻す。
7. 必要に応じて確認数量Pと原本確認根拠を入力し「反映」。未読取・欠損・変更数量には理由が必要。未登録JANは対象外と表示し、登録済みJANがPDFにない場合は確認一覧に追加せず、倉庫別の未掲載件数を表示する。対象を増やすにはマスタ登録後に画面を開き直す。
8. 担当者を入力し「数量を確認して在庫CSVを保存」。保存先キャンセルでは保存しない。未反映修正・未確認数量・マスタ変更・原本変更・未来の在庫基準日時・集計日不一致は停止する。
9. 新規保存先へ以下のファイルを出力。需要予測forecast.csvとforecast-review.csvを配置し、画面で共通補充条件を保存して（requirements.csv不要）、日常画面の「データを開いて計算」へ進む。既存ファイルは上書きしない。

| ファイル | 内容 |
|---|---|
| inventory.csv | 担当者確認済みのP数量・基準日時・原本識別情報 |
| source_evidence.csv | 両倉庫の原本PDFバイト列・SHA-256 |
| products.csv / pallets.csv | 使用した確認済みJAN・物理PLマスタ |
| pdf-presence.csv | 倉庫別の未掲載JAN・原本ハッシュ。取込時に原本を再解析して未掲載を検証し、当該組み合わせだけ計算から除外 |
| pdf-review.json | 元の読取ケース/バラ/C入、換算候補、修正Pと根拠、空欄ルール、原本ページ、担当者 |

同内容の確認履歴をローカルDBのpdf_inventory_reviewイベントにも保存し、使用マスタ版・明示確認・保存日時を記録する。DB記録失敗時は今回作成したファイルを取り消す。既存履歴・原本は削除しない。復元閲覧専用モードでは新規保存できない。

## 読取・安全条件

- 商品はPDF内部の13桁JANをそのまま取得。左側がページ外にあり見た目が6桁でも内部13桁が存在する例を確認済み。内部が6桁しかなければ停止し、JANの補完や末尾一致をしない。
- 倉庫は帳票内の神戸支店/杉戸営業所で識別。選択欄との相違、混在営業所、混在集計日、ページ欠落/重複/順序違いを検出する。
- 「現在」のケース/バラ列を見出し位置から読み、「商品合計」を各JANにつき1度だけ採用。ロット明細を再加算せず、当入・当出・前残は現在庫に足し込まない。跨ページの商品合計に対応。同一JANの合計が複数ある場合も勝手に合算しない。
- 確認数量候補P=現在ケース×PDFのC入＋現在バラ。商品内C入の不一致・欠損・不正数は未確認。空欄と明記された0を区別し、未確認の空欄を推測補完しない。バラがC入を超える表記も原本どおり換算し、正規化を理由に数量を変更しない。
- 出荷指示は引き続き登録済みの倉庫別物理PLで切上げ。入力在庫がケース/バラ表記でも、甲・端数パレット出荷を追加しない。
- PDFは20MB・50ページまで。ZIPはPDF候補500件まで、選択した1件だけを読み、ZIP内パスをファイルシステムへ展開しない。同名メンバーは拒否。重複PDFや別日PDFを集計する処理はない。
- 読取直後の候補は確定在庫にしない。保存時に原本バイト列を再解析して表示候補との一致、選択元PDF/ZIPの内容変化、マスタ版、必須数量を再検証する。確認後の数量だけconfirmed=yesで出力。

## 未確定・対象外

提供された出荷/予測CSVの倉庫コードは、正しいと指定された倉庫一覧と逆。PDF読取はコードを使わず営業所名で行い、この相違を解消したとは表示しない。予測CSVは基本P列のみ採用し、大口特売は別加算せず、小数は最終PL切上げまで保持する。外部コード・正式補充設定は独断で確定しない。ブンセン在庫・製造・確定入庫・輸送中は最新方式で対象外。

画像OCR・未確認レイアウト・手書き修正の自動理解は対象外。読取成功は原本の業務上の正しさや転記無誤りの保証ではない。担当者が原本・数量・基準を確認して保存する。

## 検証


PDF読取、アプリ内原本表示、修正履歴、確認CSV取込、補充計算、正式Excel/PDF出力までを検証する。self-testにも同経路を追加し、配布EXEで抽出ライブラリとPDFium DLLの動作を検証する。実PDFはローカル検証だけに使用し、原本・読取数量・認証情報をコミットしない。


## 0.7.9 入力ファイルの検査とエラー表示

取込フォルダーのPDFをすべて在庫原本と見なす処理を修正しました。inventory.csvのsource_pdfに指定されたPDFだけを監視します。出力済みの出荷指示書PDFなど、在庫原本に使わないPDFが同じフォルダーにあっても取込を止めません。入力CSV・指定された在庫PDFの読み込み中の変更、追加、削除、読取不能は引き続き検出し、取込を停止します。初回の在庫CSVの内容を保持して指定元の変更も検出します。数量計算・旧履歴の意味は変更しません。

検査エラーの画面は「入力ファイルを読み込めませんでした」というタイトルで、対象ファイル名・理由と対処を表示します。編集を保存して閉じる、コピーや同期の完了を待って再取込、繰り返す場合は入力データ一式を別の作業フォルダーへコピーして試す、という順番です。技術項目input_fileや空の倉庫・商品欄はこの画面に表示しません。数量などの別の不備がある場合は併記します。変更検出コード・ファイル名は診断と履歴に保持します。
