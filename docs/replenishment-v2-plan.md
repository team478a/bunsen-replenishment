# ムロオ必要補充方式への改修計画（2026-11-14）

## 現状調査

既存はPython 3.12 / Tkinter / SQLite、CSV連携、ローカル保存、PyInstallerによるWindows x64配布。CSV厳格検証・読取中変更検出・需要予測取込・商品別換算・改訂/原本/編集履歴・バックアップ/閲覧専用復元を再利用する。

旧補充式は対象需要総量＋安全在庫P－到着前の残高。正式発行に当日朝の乾麺在庫、ロット割当、期限、専用車重量を必須としていた。旧画面は仮指示→朝照合を中心とする。新方式はこの依存を廃止し、日別の確定入庫を含むピーク不足量を計算する。

現状のExcel出力・PDF自動生成は未実装（印刷HTMLからブラウザーPDFのみ）。特定業務Excelとの連携実装はない。今回の訂正により、添付Excelの取込・セル差込・数式保持は開発対象外で、添付ファイルに変更しない。出力はアプリの確定内容から直接生成する。

## 新しい計算契約

- v2専用のreplenishment.csvでモードを識別。必須は商品、ムロオ在庫、日別予測、確定輸送中/入庫、補充条件。乾麺在庫・車両/ロット/期限は参照も検証もしない。旧入力は新規業務操作に使用しない。
- 在庫basisをopening/closingで明示し、基準日の需要を含める/翌日から含めることを区別する。日中途中の現在庫に日次予測全量を無条件に重ねない。実CSVの切時刻対応は未確認。
- 到着日=出荷予定日＋商品/倉庫別lead_days。対象日数=max(cycle_days,coverage_days)とし次回補充まで/明示対象期間の長い方をカバーする。値は確認済み設定を必須とし本番初期値を推測しない。
- 各日の安全在庫Pは翌日からsafety_days日分の既存需要予測合計。必要予測は在庫基準から対象末日＋安全在庫日数まで必要。ゼロ日数は明示設定の場合のみ0。
- 確定入庫はIDを一意にし、在庫に取り込まれた基準日以前の入庫は拒否する。網羅確認日時を在庫日時と一致させる。明示的なヘッダーのみの入庫CSVと網羅確認を0件宣言として扱う。
- 補充前の日別残高=前日残高＋同日確定入庫－日別予測。到着日以降の各日について安全在庫－補充前残高の最大値を必要補充Pとする。遅い入庫で早い不足を隠さない。到着前の負残高と日内入庫順は警告する。
- 甲P=p_per_ball×balls_per_caseで必要Pを切り上げる。PLは甲数のまとまりとしてPL＋甲を表示し、丸ごとのPLへの過剰切上げはしない。旧式との差は仕様変更としてテストする。
- 外部のconfirmed/provisional/imputed予測を明示区分。暫定利用は担当者が選択した参考計算のみで、必要期間に未確定予測を使った正式発行は停止。アプリ内で補完・学習・予測生成はしない。

## 実装順序

1. AGENTS/仕様/契約を新指示に合わせ更新し、旧仕様を履歴資料として保持。
2. v2入力・日別計算・甲切上げ・暫定予測ゲート・設定変更履歴を既存サービスへ追加。旧保存原本/帳票/バックアップの解釈は維持。
3. 日常画面を取込→分析→結果→判定/確定→出力へ変更。朝照合/ロット編集を外し、数量と修正理由を同一画面で管理。設定は管理画面へ分離。
4. 倉庫別Excel/PDFを直接生成。Excelは標準OOXML、PDFは日本語対応ライブラリを同梱し、ネット・Excel本体を不要にする。必要補充指示と実出荷実績を明確に区別。
5. 架空v2サンプル・固定日付デモ・旧互換テスト・新業務テスト・Windows配布検証を実行しPR作成。

実CSV接続、入力の切時刻、営業日/締時刻、各補充設定の正式値、外部予測の確認責任者、実プリンター/現場受入、実出荷実績連携は未確認。今回の計算・確定は供給可能在庫や実出荷を保証しない。
