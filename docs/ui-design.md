# 現場UIのデザイン

## 方針と構成

既存Tkinter構成を使い、Windows単体・オフラインの配布方式を維持する。画像・外部フォント・Web接続は不要。計算式、CSV契約、保存原本、履歴、確認・発行条件は変更しない。

- 上部：濃紺のアプリ名と保存モード。架空試用・復元閲覧専用は常時表示する。
- ナビゲーション：補充出荷 → 14日配送計画 → 商品マスタ → 管理・履歴 → バックアップ・復元 → 取込前診断。日常操作を先頭へ置く。
- 補充出荷：取り込み・分析、結果表、選択数量・理由の修正、担当者確認、保存・正式確定・Excel/PDF出力、計算根拠の順。神戸・杉戸の明細と元の計算値を同じ表で比較する。
- 配送計画：計画日と計算、明示確認と確定・出力、便別表、状態・概算期限リスク・根拠、保存計画選択。
- 商品マスタ：一覧・CSV出力、転記、商品・単位・期限の2列フォーム、換算確認、担当者・理由・確認チェック、保存。業務値を補完しない。

## 見た目と状態

背景は淡い青灰、結果と根拠は白、見出しは濃紺。主要操作を青緑に統一し、参考保存と正式確定をラベルでも区別する。表見出し・行の高さを確保し、数値列を右寄せする。大きな見出しと日本語の操作名を使う。

日常操作は「未計算」「未確定」「正式確定済み」、明細数、検証不備数、注意明細数を表示する。計算行の警告または必要P未達の行を薄い橙色で示す。色だけで判断させず、詳細な理由・対象は根拠欄に残す。「不備0件」は担当者確認や期限適合の保証を意味しない。

データ・設定の変更時は未計算へ戻す。従来の再検証・確認解除・履歴保存を継続し、見た目だけで確認済みにしない。

## 画面サイズと操作

初期サイズ1180×820、最小1000×650（Tk座標）。Windowsの拡大表示で下部が隠れる場合も、4つの業務・管理ページは右端の縦スクロールで末尾まで移動できる。ページ上のマウスホイールでも移動できる。表は専用の縦・横スクロール、根拠欄は専用の縦スクロールを使う。表・根拠欄のホイールをページ移動で奪わない。長い品名・日付は列幅変更と横スクロールで参照する。

既存のバックアップ・診断は機能を維持し、共通テーマのみ適用する。旧方式の業務画面を新方式へ再導入しない。

## 検証・運用確認

既存262テストと起動診断15項目で、数量修正、正式確定、商品登録、履歴再表示、Excel/PDF出力の互換性を確認する。固定日付デモも実行する。Windowsの架空試用画面で補充・配送計画・マスタ・管理の配置、ページスクロールと下部の保存/確定操作への到達を確認する。

実データ接続と現場担当者による使いやすさの受入は別途必要。すべてのDPI・画面解像度・支援技術の適合は未確認。業務設定の正式承認や概算期限の実期限保証を追加するものではない。
